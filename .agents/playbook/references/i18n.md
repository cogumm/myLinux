# i18n (pt / en)

Shared UI strings for Carcará **1.x** and **2.0**.

## Source of truth

| Path | Role |
|------|------|
| `locales/pt.json` | Portuguese (default) |
| `locales/en.json` | English |
| `carcara/app/config/i18n.sh` | Bash `t KEY` + `CARCARA_LANG` |
| `carcara-electron/src/renderer/lib/i18n.ts` | Renderer `t()` / `setLang()` |

## Selecting language

```bash
export CARCARA_LANG=en          # 1.x menus (Zenity)
# or in carcara-electron/.env:
CARCARA_LANG=en
```

- Explicit `CARCARA_LANG` wins (`pt` or `en*`).
- If unset, 1.x falls back to `LANG` / `LC_MESSAGES` (`en*` → English, else Portuguese).
- 2.0: Zod `CARCARA_LANG` from `.env` is the **default**; the rail **PT | EN** switch overrides via `localStorage` (`carcara.lang`) and remounts the UI. Clear storage to fall back to env again.
- Native Electron menu labels follow env until process restart.

## Patterns

- **1.x Zenity:** hidden `id` column + `--print-column=1`; `case` on stable IDs; labels via `$(t …)`.
- **2.0:** set lang before license gate; views use `getMeta()` / `t()` at render time.
- Product names (Git, Discord, VLC, Carcará, Ko-fi, …) stay untranslated.
- Technical tile hints (`apt → Flatpak → Snap`, paths) may stay English.
- Brand marks (`cogumm.net`, version `2.0`) are not localized.

## Add a string

1. Add the key to **both** `locales/pt.json` and `locales/en.json`.
2. Use `t "key"` (Bash) or `t("key")` (TS).
